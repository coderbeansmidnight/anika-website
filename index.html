About

I'm a software engineer who splits time between building production backend systems and the machine learning models that rely on them. I like the problems that live at that boundary — getting a model from a notebook into something that serves real traffic, reliably, at reasonable cost.

Most recently I've been working with Python and Go on the backend, and PyTorch for model work. I care about code that's easy for the next person to read, and about the parts of ML engineering that don't show up in a paper: data pipelines, monitoring, and knowing when a model has quietly started to drift.

Outside of work I contribute to a couple of open source projects and write occasionally about things I've learned the hard way.
